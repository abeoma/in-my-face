# 要件

本書は利用者に対する振る舞いと受け入れ条件を定義します。実装案は[アーキテクチャ](architecture.md)に記載します。MustはMVP必須、Shouldは実機検証で対応範囲を確定する目標、Couldは将来候補です。

CAL-01〜03、REL-04、NFR-01〜02の検証に用いる[EventKit検証アプリ](validation/eventkit-probe.md)があります。終日・例外回・識別子を表示する診断用UIであり、製品の受け入れ条件の達成を示すものではありません。製品の要件は以下のとおりです。

ALT-02〜05、NFR-02・06の表示・操作検証には[オーバーレイ検証アプリ](validation/overlay-probe.md)を使います。15秒の自動停止は試作の検証用機能であり、REL-04で定義する製品アラートの終了条件には適用しません。

## 機能要件

| ID | 優先度 | 要件・受け入れ条件 |
| --- | --- | --- |
| CAL-01 | Must | EventKitで複数カレンダーを列挙する。初回は説明後にFull Accessを要求し、拒否・制限・writeOnlyでは取得と通知を停止して設定への案内を表示する。予定への書き込みはしない。 |
| CAL-02 | Must | 通知対象を複数選択でき、再起動後も保持する。初回は未選択で案内を表示。新規追加カレンダーは自動選択しない。消えたカレンダーは対象から除外し状態を知らせる。 |
| CAL-03 | Must | 終日・キャンセル済みの予定を除外する。会議URLの有無では除外しない。繰り返しの各回と例外回を別々に扱い、追加・変更・削除を次回評価へ反映する。 |
| ALT-01 | Must | 0・1・3・5分前から1つを選択し、初期値は1分前。正常稼働中の検証環境で通知予定時刻から2秒以内を受け入れ目標とする。OSによる遅延の保証値ではない。 |
| ALT-02 | Must | 通常通知の代わりに独自オーバーレイを表示し、会議名（空欄時は「名称未設定」）、ローカル開始時刻、残り時間を提示する。開始後は「開始済み」とする。 |
| ALT-03 | Must | Dismissと、検出URLがある場合のJoinを提供する。URLなしはJoin無効と理由を表示。Escは現在選択した予定のDismiss。通知音は初期OFFで、ON時は通知バッチごとに一度だけ再生する。 |
| ALT-04 | Must | 通常デスクトップでは接続中の各ディスプレイを覆うウィンドウを表示する。操作は共通状態へ反映し、キーボード操作の対象は1ウィンドウだけとする。画面着脱でも操作不能にならない。 |
| ALT-05 | Should | 複数Space、他アプリのフルスクリーン、Stage Managerでも表示を試みる。対応OS・表示構成別に実測し、成功条件と失敗条件を公開する。ロック画面等を覆うことは要求しない。 |
| URL-01 | Must | 予定のURL、場所、メモから対象4サービスのHTTPS会議URLを検出する。複数候補はURL→場所→メモの優先順、同一フィールド内は出現順で第一候補を選び、他候補も選択可能にする。 |
| URL-02 | Must | Joinの明示操作で選択URLをOSへ渡す。ホストを表示して誤検出を確認可能にする。開く処理が失敗したら閉じずに再試行できる。自動参加や事前アクセスをしない。 |
| MENU-01 | Must | Dockに原則表示せずメニューバーに常駐。次の対象予定、選択カレンダーの当日予定、設定、終了を提供する。予定なし・権限なし・未選択を区別する。 |
| MENU-02 | Must | 一時停止中は表示中アラートも閉じ、新規表示・音を止める。再開まで維持し、再起動を跨ぐ。再開時はREL-01の規則で再評価し、過去分をまとめて鳴らさない。 |
| SET-01 | Must | 通知時刻、対象カレンダー、音をローカル保存する。変更時は未処理予定を再評価する。ログイン時起動は初期OFF、明示ON/OFFと実際のOS登録状態・承認待ちを表示する。 |

当日一覧は現在のタイムゾーンの一日と重なる予定を開始順に示し、終日予定には「通知対象外」を表示します。次の予定は開始前の通知対象予定で、Dismiss済みでも予定自体は表示します。

## 信頼性とエッジケース

| ID | 優先度 | 要件・受け入れ条件 |
| --- | --- | --- |
| REL-01 | Must | 起動・復帰・ロック解除・再開・時刻変更時に再取得する。通知時刻を過ぎた未処理予定は、開始前または開始から2分未満、かつ終了前なら即時表示。それ以外は通知しない。未起動・スリープ・ロック中の表示を保証しない。 |
| REL-02 | Must | 同一回のアラートは評価の多重実行、画面数、変更通知の連発で増殖しない。Join成功・Dismiss済みの回は再起動後も再表示しない。通常の予定編集でも処理済み状態を維持する。識別子変更時の限界はADR-04に従う。 |
| REL-03 | Must | 同じ通知時刻の複数予定は一つの一覧で提示する。別の予定が到来したら同じ表示へ追加する。各回を独立にJoin/Dismissでき、操作のない予定を勝手にDismissしない。 |
| REL-04 | Must | 削除・キャンセル・対象外化した予定は予約と表示から除く。表示中の時刻変更で通知時刻が未来になれば表示を閉じて再予約する。終了時に閉じるが、開始しただけでは閉じない。 |
| REL-05 | Must | システム時刻・タイムゾーン・日付変更で再評価し、残り時間と当日一覧を更新する。夏時間を含め、絶対時刻と現地表示を混同しない。連続する会議はそれぞれ通知する。 |

## 非機能要件

| ID | 優先度 | 要件・受け入れ条件 |
| --- | --- | --- |
| NFR-01 | Must | カレンダー情報を外部送信しない。バックエンド、分析SDK、独自同期、URL検証の通信を設けない。Join後のブラウザー・会議アプリやOS自身のカレンダー同期は別の動作として説明する。 |
| NFR-02 | Must | 公開APIのみ使用し、権限拒否・撤回を尊重する。画面収録、Accessibility、管理者権限を前提にしない。会議名・メモ・URL・参加トークンをログへ出さない。 |
| NFR-03 | Must | 秒単位の常時ポーリングを行わない。暫定計測目標は予定1000件・待機10分で平均CPU 1%未満（1コア比）、メモリ100MB以下。測定機・OS・Release条件を記録し、超過時は原因と予算を再審査する。 |
| NFR-04 | Must | 自動起動をONにしてOSが許可した場合、次のユーザーログインで起動する。再起動後も同様。ログイン前の起動、ユーザーが無効にした項目の復活、終了後の自動復活は行わない。 |
| NFR-05 | Must | スケジューラーと抽出は時刻・予定を差し替えて単体テストできる。ウィンドウ・権限・ログイン項目は実機で検証し結果を残す。 |
| NFR-06 | Must | Join/DismissをキーボードとVoiceOverで操作できる。文字のコントラストを確保し、通知音OFFでも操作できる。 |
| FUT-01 | Could | スヌーズ、終日通知、任意サービス追加、テーマ等。MVPの受け入れ対象には含めない。 |

## 保証の境界

定刻性は、権限あり・対象選択済み・起動中・停止解除・スリープせずロックされていない条件で評価します。カレンダー提供元からOSへの同期遅延はアプリでは制御できません。異常終了直前の永続化、アカウント再同期による識別子変更では完全な重複排除を保証せず、既知の制限として記録します。
