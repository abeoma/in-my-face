# コード・セキュリティレビュー

確認日：2026-10-20。対象は最小リマインダーの初期実装（`d3dbe8e`）と、その修正差分です。コードとセキュリティを独立した2つのサブエージェントがhighの推論強度で読み取りレビューし、修正差分も再レビューしました。実カレンダー・ロック画面・別ユーザーの画面を使う侵入試験は実施していません。

## 指摘と対応

P0/P1相当の権限回避、不要通信、機密ログの問題は見つかりませんでした。これは安全性の完全な保証ではなく、対象コードと設定のレビュー結果です。

| 優先度 | 指摘 | 対応 |
| --- | --- | --- |
| P2 | 画面復帰が、残っているセッション非アクティブ等の停止理由まで解除する | 修正済み。停止理由を独立した集合で管理し、対応する復帰だけで解除。終了理由も復帰通知では解除しない |
| P2 | 起動時に即時表示したアラートから設定画面がキー対象を奪う | 修正済み。設定ウィンドウを開いてから通知評価を開始 |
| P2 | 起動時の期限切れ履歴がメモリだけから削除され、ファイルに残る | 修正済み。ロードで削除した行も原子的に保存し、失敗時は後で再試行 |
| P2/P3 | Dismiss保存の失敗後、状態が変わらないと保存を再試行しない | 修正済み。書き込み成功までdirty状態を維持。回復後は一時的な警告を解除し、起動時に失った履歴への警告は維持 |
| P3 | 破損バックアップに個数・期限の上限がない | 修正済み。台帳ディレクトリ直下の予約名・通常ファイルだけを対象に、最新1件・発見後7日までに制限。起動・再評価時に処理 |
| P2・保留 | Dismiss後、検索範囲より先へ延期した回が再取得前に期限切れとなる | 設計課題として残す。個人利用では再通知時に再Dismissし、通常のCalendar通知を併用。REL-02全体の合格にはしない |

## 大きな変更を避ける運用範囲

Dismissした会議を30日先へ移すと、48時間の取得範囲では新しい終了日時が見えないまま、最後に取得した終了日時＋7日で履歴が消えます。識別子が変わらなくても、再び取得範囲に入ったときに通知されます。現在の単体テストで、取得済みSnapshotの終了日時更新が成功することは、この取得境界を越えた追跡の証明にはなりません。

個人alphaでは再Dismissを許容し、無期限の履歴保存や全カレンダーの無制限取得を追加しません。配布前に対象指定取得の検証、保持期間と検索範囲の見直し、または要件の保証範囲の確定が必要です。制限を文書化しただけで不具合が解消したとは扱いません。

初期版はアクティブなログインセッションで手動起動し、標準のCalendar通知を補助として残します。画面共有・投影・ユーザー切替の前には一時停止し、戻ってから明示的に再開します。共有した画面や外部ディスプレイに会議名が見える仕様は残ります。ロックの確実な検出、非アクティブセッションで起動した際の初期状態把握、大量予定での応答性は未確認です。これらを秘匿や定刻配信の保証として案内しません。

ファイルシステムが書き込み・削除を拒否した場合は、保存や期限・個数の制限を保証できません。エラーは画面へ伝え、次の再評価で再試行します。実機確認の範囲は[最小リマインダーの検証記録](minimal-reminder.md)に記載しています。

## 会議URLとJoinのレビュー（2026-10-21）

対象はMeetingURLExtractor、Snapshot・EventKit連携、Join・候補選択、テストと関連文書です。highの推論強度のサブエージェントによる読み取りレビュー後、指摘を実コードで再現し修正しました。既存のEventKitProbe署名設定の変更は対象外です。

| 優先度 | 指摘 | 対応 |
| --- | --- | --- |
| P2 | URL型の予定URLにも文章用整形が適用され、末尾の参加トークンやパスが変わる | URL型入力は直接検証し、補正しない。場所・メモでもクエリ・fragmentの末尾を削除しない。回帰テストを追加 |
| P2 | Webexの`j.php`のドットが正規表現の任意文字で、`jXphp`も受理する | ドットをリテラル化し、類似パスを拒否する回帰テストを追加 |
| P2 | クエリだけ異なる会議候補の表示文字列が同じ | 候補番号を表示し、抽出順に対応付ける。クエリ・参加トークンは表示しない |
| P3 | 制御文字を含むパスが表示を乱す | デコード後のパスの制御文字を拒否し、改行・タブのケースを追加 |
| P3 | デモの架空IDと実会議のIDが重なる可能性 | デモのJoinは外部URLを開かず、成功を模擬する |

任意ホストへのオープン、抽出時の事前通信、URLの台帳保存、会議情報のログ出力につながる経路は見つかりませんでした。実サービスのリダイレクト先・会議入室は検証しておらず、信頼性を保証するものではありません。

大きなHTMLパーサーや短縮URL展開は導入しません。予定URL欄または空白で区切った裸のHTTPSリンクを利用し、候補の内容が不明・検出できない場合はCalendarの元の招待から参加します。候補番号はクエリ内容を説明するものではありません。配布前には4サービスの実予定、実ブラウザー引き渡し、キーボード・VoiceOverの確認を残し、運用説明だけでURL-01〜02・NFR-06全体の合格とはしません。

修正後は同じサブエージェントが再レビューし、追加の重大な指摘はありませんでした。Apple Development署名のビルド、XCTest 29件（失敗・skipなし）、`swift-format lint --strict`、`git diff --check`、ローカルリンク38件の確認が成功しています。表示とOS連携の実機マトリクス全体を再実施した結果ではありません。
