# 開発計画

MVPに向けた技術検証・実装の順序と、各段階の完了条件を定義します。

個人利用向けの最小実装は、P1〜P4のうちカレンダー選択・1分前通知・Dismiss・履歴・一時停止を先行して組み合わせています。[確認結果と残課題](validation/minimal-reminder.md)を参照してください。P0の未確認項目は残し、通常利用で確認を進めます。各マイルストーンやMVP全体が完了したという扱いにはしません。

[コード・セキュリティレビュー](validation/code-security-review.md)で検出した小規模な不具合は修正し、停止理由と履歴の回帰テストを追加しています。検索範囲外へ延期した回の追跡は未解決です。個人利用では通常通知の併用と再Dismissで対処し、配布前にREL-02の追跡方式または保証範囲を確定します。全履歴の常時取得や無期限保存は追加しません。

MeetingURLExtractor・参加先選択・Joinは実装済みです（URL-01〜02、ALT-03のJoin部分）。抽出とオープン失敗・再試行の自動テストを追加しています。レビューでURL型入力の保持・Webexのパス検証・候補番号を修正しています。完全なHTML解析と任意のURL形式への対応は追加せず、判別できない場合は元の招待から参加します。4サービスの実予定サンプル、OSへの引き渡し、VoiceOverとキーボードの実機検証は残っています。対応形式は[アーキテクチャ](architecture.md#url抽出の現在の対応範囲)を参照してください。

| P1：アプリ基盤 | Xcode構成、Bundle ID、署名、LSUIElement、メニューバー、設定永続化、権限導線。 | 起動・終了・拒否・再許可が動作し、対象カレンダーと設定が再起動後も残る。READMEに実際のビルド・テスト手順を記載。 |
| P2：予定取得 | CalendarService、期間検索、Snapshot、変更再取得、当日・次の予定一覧。 | CAL-01〜03とMENU-01を検証。繰り返し例外、削除、終日、未選択、空の予定一覧を扱える。 |
| P3：スケジューリング | 差し替え時計、通知時刻計算、単一タイマー、回台帳、停止・再開、復帰・時刻変更。 | ALT-01、REL-01〜05、MENU-02が決定的なテストで成立し、再起動後も処理済みを抑止する。 |
| P4：表示・参加 | Overlay、複数予定、画面着脱、音、URL抽出、Join、キーボード操作。 | ALT-02〜05、URL-01〜02、NFR-06を検証。P0の表示マトリクスを本体でも再確認し、既知制限を公開。 |
| P5：配布前の信頼性 | Login Item仕上げ、エラー回復、権限撤回、長時間稼働、署名・配布検証。 | SET-01、NFR-01〜05の証拠を記録し、Mustをすべて合格。Shouldの結果と未対応範囲をREADMEへ反映。 |

## P0の技術検証

EventKit検証アプリは`Prototypes/EventKitProbe/`にあります。[検証手順・結果](validation/eventkit-probe.md)にビルドと初期画面の確認結果を記録しています。Full Access許可後の取得・拒否・撤回・繰り返し識別子の検証は未実施です。P0全体は未完了です。

- EventKit：未決定・fullAccess・拒否・制限・writeOnly、OS設定での撤回と再許可。変更通知後の再取得、iCloud等の同期遅延を観測する。
- 回の識別：単発の時刻変更、シリーズ全体編集、1回のみ変更・削除、カレンダー移動、アカウント再同期で識別子とoccurrenceDateの安定性を確認する。個人情報を除いた試験データを使う。
- 表示：対応最小OSと採用する最新安定OS、通常・別Space・他アプリフルスクリーン・Stage Manager、単一／複数画面、画面ごとの個別SpaceのON/OFFを組み合わせる。フォーカス、Esc、VoiceOver、画面着脱、メニューバーからの停止・終了を確認する。
- ライフサイクル：通知期限を跨ぐスリープ・ロック・再起動、日付・時刻・タイムゾーン・夏時間変更、ログイン項目のOS側無効化を検証する。ロック解除の公開通知と状態検出方法を確定する。
- URL：各サービスの通常リンク、テナント別リンク、Teamsの複数形式、Webexの個人会議室を匿名化サンプルで確認する。未対応形式を公開し、検証のための外部アクセスはアプリへ追加しない。

表示試験は「OS／アプリ版／画面構成／Space設定／前面アプリ／API構成／期待／実測／制限」で記録します。P0でAPIの組合せを選び、P4で製品として再試験します。試験結果は`docs/validation/`へ保存します。

## テスト計画

| 対象 | 手段と主要ケース | 対応要件 |
| --- | --- | --- |
| Scheduler | XCTest＋固定時計。0/1/3/5分、開始直前・開始後119秒/120秒、終了済み、同時刻、連続、停止・再開、逆向きの時計変更、古い取得結果の破棄。 | ALT-01、MENU-02、REL-01〜05 |
| 回台帳・設定 | 一時ディレクトリと隔離UserDefaults。再起動相当の再読み込み、予定編集、例外回、保持期限、破損JSON、保存失敗、設定移行。 | CAL-02、SET-01、REL-02 |
| URL抽出 | 通信なしのテーブルテスト。4サービス、候補優先順位、複数候補、句読点、HTMLを含むメモ、偽装ホスト、不正URL、独自スキーム。 | URL-01〜02、NFR-01〜02 |
| CalendarService | 合成Snapshotの境界テストと、専用テストカレンダーで実機統合試験。権限、変更・削除、終日、繰り返し例外。 | CAL-01〜03、REL-04 |
| UI・OS統合 | XCUITest可能な操作と実機試験。全画面共有状態、Join失敗、音一回、Esc、VoiceOver、表示制限、ログイン後起動。 | ALT-02〜05、NFR-04、NFR-06 |
| 性能・プライバシー | ReleaseのInstruments等で待機CPU・メモリ・wakeupsを計測。ソース・ログ・通信を点検し、OSやJoin先の通信と区別。 | NFR-01〜03 |

## リリース判断

Mustの未合格はリリースを止めます。APIで保証できない環境は、成功を仮定した自動テストで代用せず制限として記録します。クラッシュ直前の永続化と識別子全面置換の限界も利用者向けに説明します。既知問題、実測結果、実際のコマンド、署名・配布手順を更新した時点でMVP完了とします。日程の見積もりはP0の結果を受けて行います。
